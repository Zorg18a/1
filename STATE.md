# Состояние проекта — 2026-11-08

## Вложенные игровые папки

- Старый режим `auto` раскрывал только каталоги `new1`, `part2` и подобные, поэтому
  произвольная категория могла восприниматься как игра. Существующий `nested` раскрывает
  ровно один уровень категорий; добавлен `nested2` для двух. `flat` и `auto` сохранены.
  В настройках MediaHub теперь можно выбрать структуру автосканирования, а в GameSweep —
  структуру текущего сканирования. Изменение настройки само не запускает пересканирование:
  нужно выбрать ту же структуру в «Игры → Версии» и нажать «Сканировать».
- При правильно выбранной глубине внутренние каталоги игры не становятся играми. Ссылки
  и reparse points пропускаются при перечислении и подсчёте размера; ошибка чтения
  категории прерывает сканирование и не вызывает синхронизацию. Это не защита от
  подмены путей и не полная оценка доступности вложенных файлов/размера. Выбранный
  неправильный уровень может принять категории или внутренние каталоги за игры.
- Синхронизация больше не удаляет и не очищает невстреченные карточки: они сохраняются,
  даже при смене структуры или недоступности файлов. Если путь пропал, игра отображается
  как не скачанная; очистка карточек теперь только вручную. Тесты не затрагивают реальные
  данные. Локально: 172 Python-теста (7 Windows-only пропущены), 57 Node-тестов,
  compileall, JS, GameSweep selftest 73/73 и `git diff --check` прошли. Windows CI,
  включая тест junction и Edge на временной библиотеке, ожидается.

## UX: подтверждение входящих и срок хранения

- Тексты больше не обещают закрытия вкладок; оно отдельно разрешается и зависит от
  успеха и ответа браузера. «Только сохранить ссылки» переводит выбранные скачивания,
  игровые карточки и отслеживание в ссылки; пропуски и уже имеющиеся записи сохраняются.
  Новая ссылка плейлиста больше не включает отслеживание, но ранее включённое не снимается.
- Отправка проверяет HTTP/JSON и счётчики, блокирует повторные нажатия до ответа и даёт
  постоянное сообщение. При сбое результат неизвестен: часть строк могла обработаться;
  автоматического повтора нет, нужно проверить входящие, загрузки и библиотеку. В одном
  процессе подтверждения сериализованы, повторные ID одного запроса пропускаются.
- Это не атомарность и не полная идемпотентность: сбой между созданием задания и записью
  состояния может дать дубликат при ручном повторе, а несколько процессов не защищены.
  Срок жизни очереди/истории заданий и 200 событий уведомлений указан в интерфейсе;
  постоянное восстановление очереди и история уведомлений по-прежнему не реализованы.
- Локально прошли 160 Python-тестов (6 Windows-only пропущены), 53 Node-теста, compileall,
  синтаксис JS, GameSweep selftest 73/73 и `git diff --check`. HTTP и конкурирующие
  запросы тестировались на временной БД. Windows CI run 42873937591 для 9f4bb04
  успешно прошёл Python/Node, headless Edge (ссылки, opt-in и неопределённый результат),
  сборку EXE и packaged smoke. Ручные проверки и реальные пользовательские данные не использовались.

## UX: подтверждение удаления

- В медиатеке и карточке игры удаление проходит через общий диалог с последствиями;
  для файлов показан путь и предупреждение о безвозвратном удалении папки или соседних
  файлов. Игровые файлы не удаляются, но запись и её теги/заметки будут потеряны.
- В диалоге удаление требует совпадения подтверждённых title/kind/path/root с текущей
  записью; старые клиенты `files:true` без этих полей получают ошибку, прежние запросы
  только на удаление записи по-прежнему поддерживаются. Ошибки файловой
  системы больше не скрываются: запись сохраняется, но часть файлов могла уже удалиться.
  При ошибке удаления записи после файлов сервер предупреждает о возможной потере файлов.
- Ограничения: по-прежнему нет предварительного полного списка соседних файлов, безопасной
  проверки корневого пути и защиты от внешней подмены; удаление не атомарно и не в Корзину.
  Это не относится к будущей установке игровых обновлений, которая не реализована.
  Локально: 158 Python-тестов (6 Windows-only пропущены), 49 Node-тестов, compileall,
  синтаксис JS, GameSweep selftest 73/73 и `git diff --check` прошли. Тесты удаления
  используют временные файлы. Windows CI run 42871595879 для 9d690bb прошёл тесты,
  headless Edge (диалоги и отказ удаления), сборку EXE и packaged smoke. Дополнительная
  проверка актуальности для удаления только записи прошла Windows CI run 42872172068
  для fc2e1f8 с теми же этапами. Ручные тесты на реальных пользовательских данных не проводились.

## Сохранность: изолированное восстановление SQLite

- Подготовлены проверка и восстановление резервной SQLite-копии в новый файл без
  перезаписи. Применяется SQLite backup для WAL, затем integrity_check и минимальная
  проверка таблиц; ошибки оставляют частичные файлы для диагностики. При успехе возможный
  неудалённый partial возвращается вызывающему коду. Это изолированный эксперимент,
  **не подключён к приложению**, не восстанавливает настройки/медиа и не является
  пользовательским мастером. Ограничения доверенных путей, ACL, hard links, подмены,
  лимита времени и durability описаны в `docs/player-reader-plan.md`.
- Тесты используют только временные базы; локально прошли 157 Python-тестов
  (6 Windows-only пропущены), 44 Node-теста, compileall, синтаксис JS, GameSweep
  selftest 73/73 и `git diff --check`. Windows CI run 42848878740 для 2c72954 прошёл
  Python/Node, Edge smoke, сборку EXE и packaged smoke. Восстановление проверено только
  автоматическими тестами на временных файлах, не на реальных пользовательских данных.

## UX: отмена и вкладки — в работе

- Массовая отмена спрашивает подтверждение со снимком активных и запланированных заданий;
  запросы идут по ID, не затрагивая появившиеся позднее. Частичные файлы могут остаться,
  отмена асинхронна; ошибки отправки показываются. Расширения предлагают закрытие вкладок
  только по явному выбору, для распознанного `сохранено частично` вкладка остаётся открытой.
- После перезапуска отсутствие заданий теперь не считается успехом даже при наличии файла;
  вкладка остаётся открытой. Изначальный риск скрытых ошибок плейлистов частично снижен
  следующим этапом, описанным выше; гарантия полноты загрузки не заявляется.
- Локально: 145 Python-тестов (6 Windows-only пропущены), 42 Node-теста,
  compileall, синтаксис JS, `git diff --check`, GameSweep selftest 73/73 прошли.
  Windows CI run 42822068134: Python/Node прошли, Edge smoke упал из-за гонки ожидания
  диалога в тесте; сборка не запускалась. Ожидание события исправлено; повторный Windows

## Архитектурная доработка — этап 4: основа защищённого чтения

- Добавлен изолированный экспериментальный Windows NTFS-примитив чтения, не подключённый
  к API и интерфейсу. Он открывает каждый компонент с OPEN_REPARSE_POINT и удерживает
  дескрипторы каталогов без разрешения удаления/переименования, файл — без разрешения
  записи/удаления; отклоняет reparse points, спецфайлы и жёсткие ссылки. Допустим только
  локальный фиксированный NTFS, чтение блоками до 1 МиБ. На других системах — отказ.
- Это не готовое безопасное копирование: абсолютные открытия не используют handle-relative
  traversal; переназначение диска, существующие отображения памяти, изменение состава
  папок и блокирующий ввод остаются нерешёнными. Примитив не создаёт копий; его нельзя
  использовать как утверждённый манифест или бэкап до отдельных проверок и интеграции.
- Локально: 82 Python-теста (4 Windows-теста пропущены на Linux), 21 Node-тест,

## Решения и ограничения

- Интерфейс — локальная веб-страница, а не нативное окно. Host/Origin проверки сохранены.
- Целевая архитектура и лимит 200 строк ещё не достигнуты: два больших файла `legacy/`,
  `ui/index.html` и два background.js — зафиксированные исключения. Legacy по-прежнему
  смешивает HTTP, логику и данные; единый формат ошибок не применяется ко всем старым маршрутам.
  Не обещаем, что функции вне проверенных сценариев не сломаны.
- Зависимости намеренно не зафиксированы версиями, как в оригинале; воспроизводимость ограничена.
