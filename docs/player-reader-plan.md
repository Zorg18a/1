# План: плеер, читалка 2.0 и «Продолжить»

Исходное предложение: [спецификация от 2026-11-10](2026-11-10-mediahub-player-reader-design.md),
её статус — «на проверке». Ни дата, ни предполагаемый там фундамент не подтверждают,
что функции уже работают. План адаптирован к текущей ветке; Smart Update остаётся отдельным
незавершённым направлением ([план](smart-update-design.md)).

## Проверка текущего состояния

| Направление | Уже есть | Отсутствует / ограничения |
|---|---|---|
| Медиа | `/f/<id>` отдаёт файл; yt-dlp сохраняет SRT (`legacy/app.py`). | `/p/<id>`, API плеера, возобновление, выбор субтитров и ошибки плеера отсутствуют. `H.file` распознаёт часть Range, но suffix и выход за границы корректно не обрабатывает: seek и 416 требуют тестов и исправления. |
| Читалка | `/m/<id>`, `/api/manga`, `/mi/`, лента, кнопки/выбор глав и сохранение страницы (`ui/reader.html`, `legacy/app.py`, `storage/database.py`). | Режимы ширины/высоты/исходного размера, масштаб, новые клавиши, фокус и озвучивание главы не реализованы. |
| Прогресс | `progress(slug,cid,page)` и `/api/progress`. | Приложение не хранит время обновления манги и позицию медиа; `/api/continue` и блок в библиотеке отсутствуют. Миграция и правила позиции подготовлены изолированно, но к запуску приложения не подключены. |
| Доступность | `ui/preferences.js`, `ui/accessibility.css`, `ui/hotkeys.js`: тема, масштаб, контраст, переключатель горячих клавиш, справка. | Реальные ключи `mediahub.display.v1` и `hotkeys`, не `mh.prefs` / `keys`; настройки подключены к основной странице, не к читалке. Указанные в предложении общие `announce`, `initRadios` и j/k-навигация карточек отсутствуют. |
| Тесты | Python unit/integration и Node-тесты, Windows CI. | Указанные 175 прежних тестов и `tests/vendor/axe.min.js` не обнаружены; нет тестов этапа 2, реальной проверки NVDA и подтверждения WCAG 2.1 AA. |

В приложении используется ограниченный allowlist файлов `ui/` и проверки Host, Origin,
`X-MH`; новые страницы и API должны сохранить их. `legacy/app.py` и `ui/index.html` —
исторические исключения из ограничения 200 строк; увеличивать их нельзя (AGENTS.md).
Интеграция потребует осмысленного извлечения существующих обработчиков с тестами,
а не простого добавления строк к монолитам. Изолированный `storage/playback.py` пока
не вызывается из приложения; уже существующие методы и формат базы не изменены.

## Поэтапная реализация и критерии

1. **Данные и безопасность.** Подготовить правила позиции, SQL и тесты на временных
   старых/новых БД, повторной миграции, ошибках и сохранении данных. Перед подключением
   к приложению спроектировать резервную копию реальной SQLite-базы через SQLite backup
   с проверкой результата, не перезаписывая существующий снимок. Отказ бэкапа должен
   останавливать миграцию; изменения схемы — в одной транзакции с rollback. Проверить
   поведение при блокировке, недоступном диске, WAL, повторном запуске и конфликте схемы.
   Обновлять `progress.updated` при сохранении, не теряя старые записи; существующий
   `insert or replace` сам по себе этого не делает. Автоматическую миграцию до готовности
   резервного копирования не включать. Удаление материала должно удалять позицию в той
   же транзакции; не удалять медиафайлы при таком очищении. Проверять `foreign_keys`
   или эквивалент, повторное использование ID и одновременные запросы.
2. **Сервер.** Выделить и покрыть HTTP-обработчики, не увеличивая исключения; API из
   спецификации с проверкой вида/ID, JSON-ошибками, Host/Origin/X-MH и сохранением
   прежних маршрутов. Проверить корректный HTTP Range для перемотки. Субтитры: только
   разрешённые соседние файлы, безопасная обработка ссылок/гонок, ограниченное чтение
   до 5 МБ, BOM, UTF-8/CP1251, SRT→VTT и стабильная индексация; тестировать обход путей.
3. **Плеер.** Нативные controls, без автозапуска, восстановление и периодическое сохранение,
   кнопка «С начала», ошибки с прямой ссылкой, дорожки и клавиши по спецификации.
   Использовать существующие настройки или согласованную совместимую миграцию, а не
   предполагать другой ключ. Не менять `open` в библиотеке до готовности страницы и API.
4. **Читалка 2.0.** Сначала безопасно извлечь существующий сценарий и проверить прежнее
   поведение; затем режимы/масштаб в localStorage, клавиатура, фокус и объявления,
   сохранение страницы и работа при недоступном хранилище.
5. **«Продолжить».** Объединить актуальные незавершённые медиа и скачанные главы манги,
   максимум шесть, без недоступных манифестов. Проверить сортировку, старые записи без
   даты, скрытие при фильтрации и удаление с предсказуемым переносом фокуса.
6. **Приёмка.** На каждом шаге полный набор Python/Node, syntax/import и регрессии;
   браузерные тесты плеера, читалки, навигации, API и безопасности; автоматический аудит
   доступности при доступных инструментах. Отдельный ручной чек-лист NVDA + Firefox и
   Яндекс Браузер, 320 px, масштаб, контраст, клавиатура, реальные Windows-пути и медиа.
   До выполнения проверок не заявлять соответствие WCAG 2.1 AA.

Текущий микроэтап: только изолированные правила позиции и экспериментальная транзакционная
миграция/хранение на тестовых БД. Они не создают резервную копию и не подключены к HTTP
или реальной БД. Следующий шаг — реализовать и проверить безопасный SQLite backup и
управляемое подключение миграции; затем продолжать в указанном порядке.
