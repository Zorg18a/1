# План объединения MediaHub без потери данных

## Цель и ограничения

Пользователь запросил пересборку с нуля со всеми функциями: Windows, Chrome/Edge,
пакеты игровых вкладок, карточки с изображением игры, жанрами и версией, проводник,
несколько игровых корней, проверку наличия игры и обновлений, постоянную память карточек,
видео, версий игр и сведений о резервных копиях рядом с программой. Второй сайт —
Pornolab; сейчас извлечение темы подключено только для F95Zone. Для Pornolab подготовлен
не подключённый парсер, проверенный лишь на синтетической разметке; нужна проверка
реальной темы и её изображений перед включением.

Пересборка ещё не готова. Рабочее приложение сохраняется до готовности и проверки
замены; можно использовать совместимые компоненты как основу, не выдавая изменения
старого приложения за завершённую новую версию. Сервер остаётся локальным. Удаление
функций и перенос пользовательских данных — только после инвентаризации, резервной
копии, проверки совместимости и подтверждения пользователя. В первую очередь нужны
сквозные тесты вкладки → карточки → связь с папкой → перезапуск и постоянная очередь;
карточки и видео уже записываются в SQLite, но очередь пока только в памяти.

## Очередность

1. **Инвентаризация и диагностика.** Описать все действующие маршруты и кнопку каждого
   действия, собрать сценарии с несколькими корнями и реальными именами. Не удалять UI,
   пока его замена не проверена. Отдельно разобрать проблему «3/50» по снимку экрана и
   версии приложения: текущий ручной `game_check` не обрезает список до 50.
2. **Связи карточка ↔ игра.** Надёжные явные связи и предварительный просмотр нескольких
   кандидатов. `Hidden Badge` и `HiddenBadge_20260828c` — возможное совпадение, а не
   доказанный дубль или порядок версий. Поиск теперь показывает снимок карточек с тем же
   записанным путём и позволяет открыть их, но не сравнивает полные метаданные и не
   обнаруживает все варианты путей. Сканер отказывается заменять вручную выбранный путь
   другим и обнаруживает устаревшую карточку, но синхронизация всей библиотеки пока не
   атомарна. Существующие автоматически созданные дубли не
   объединять без отображения обоих наборов метаданных и подтверждения человека.
3. **Единый поиск по выбранным корням.** Пользователь не обязан создавать `update`;
   сканировать выбранные места, показывать границы, пропуски, недоступные каталоги и
   незавершённые загрузки. Добавлен разовый поиск внутри указанной папки (один корень
   за раз) и подтверждаемая ручная связь без переноса; для просмотра сохранений корень
   сохраняется в карточке. Единый постоянный список корней и их автосканирование ещё не
   реализованы. Ограничения нужны, чтобы поиск не зависал на больших/сетевых
   каталогах. Никакой обход всего компьютера без выбранных корней и понятного согласия.
4. **Данные и редактор.** Сначала доказать backup-first запуск до любого изменения схемы
   старым кодом, затем миграции с тестами исторических баз, отказов и отката. Добавить
   общие метаданные и импорт пользовательских обложек; сохранять все старые данные.
5. **Обновления и сохранения.** Сначала read-only план, выбор пары игра/архив,
   распознавание сохранений и неизвестных путей, конфликты русификаторов и достаточность
   места. Затем проверяемый backup, отдельная staging-папка, журнал восстановления,
   тесты отказа на каждом шаге и только после этого экспериментальная установка. Старая
   версия удаляется лишь отдельным подтверждением после проверки новой и backup.
6. **Очередь и позиции.** Для проверки тем игровых карточек добавлено сеансовое
   продолжение ещё не начатых пунктов; оно не переживает перезапуск и не заменяет общий
   журнал. Нужны транзакционные постоянные состояния, проверяемые повторы, сохранение
   прогресса плеера и читалки, поведение при одновременных вкладках и перезапуске.
7. **Упрощение интерфейса.** После замены каждого сценария скрывать или удалять только
   подтверждённые дубли; документировать путь перехода, проверять клавиатуру, 320 px,
   NVDA и реальные расширения. Старые API отключать лишь после проверки совместимости.

## Что ещё не сделано

План не включает уже выполненную установку, общий поиск на всех дисках, универсальный
перевод, распознавание всех сохранений, автоматическое объединение дубликатов или
восстановление из резервной копии. Настоящие данные пользователя не использовались
для тестирования. Результаты проверок и нерешённые ограничения записываются в STATE.md.
