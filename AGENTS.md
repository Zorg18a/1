# Правила разработки MediaHub

- Цель: Windows, Python 3.11+, локальный интерфейс в браузере; не открывать сервер в сеть.
- `ui/` — представление, `core/` — бизнес-логика без UI, `storage/` — доступ к данным,
  `tests/` — автоматические проверки. Внешние расширения сохраняют существующий протокол.
- Новые текстовые файлы исходного кода — не более 200 строк. Не переносить код между слоями
  механическим дроблением или динамическим исполнением. На время миграции исключения:
  `legacy/app.py`, `legacy/gamesweep.py`, `ui/index.html`,
  `extension/background.js`, `extension-firefox/background.js`. Не увеличивать их;
  постепенно устранять исключения с тестами. Первые два также пока смешивают слои.
- Новый фронтенд — нативные ES-модули без сборщика; режимы отображения и клавиши —
  localStorage браузера, доступность через клавиатуру, масштабирование, контраст и ARIA.
- Для новых API-ошибок: подходящий HTTP-статус и JSON `{"error": "понятное сообщение"}`;
  внутри слоёв — конкретные исключения, транзакции с rollback, не проглатывать ошибки.
  Старые маршруты могут пока возвращать HTML-ошибки; переход без нарушения совместимости.
- Не коммитить базы, настройки, профили, cookies, токены, скачанные медиа и сборки.
  Не удалять пользовательские файлы при обновлении; перед миграцией делать резервные копии.
- После каждого рабочего шага обновлять STATE.md и при изменении состава файлов MAP.md;
  запускать тесты и указывать реальные результаты и ограничения, не скрывая техдолг.
